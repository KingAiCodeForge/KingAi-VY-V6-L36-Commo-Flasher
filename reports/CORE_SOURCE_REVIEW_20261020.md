# Core source review — 20 October 2026

This ledger records static inspection and synthetic software checks. It is not a
hardware, vehicle, flash-chip, checksum-algorithm or recovery qualification.
Line numbers change during integration; section/class names identify the scope.

| Path / section | Inspected | Qualification limits |
| --- | --- | --- |
| `kingai_commie_flasher.py`, section 1 | Device/mode/bank/sector enums, erase maps, write ranges, checksum locations and retry/timing constants; structural consistency against the code using them. | ECU addresses, chip geometry, board wiring, timing and electrical correctness were not established. |
| Section 2 | All `DataStreamParam` fields, Mode 1 parameter definitions and lookup construction; parsing/conversion use in section 5. | Parameter addresses, units and conversions were not checked against an independently verified ECU definition or a physical sensor. |
| Section 3 | `CalibrationTable`, table byte-size calculations, dimensions, offsets, axis metadata and downstream access. | Calibration/XDF identity and whether these tables belong to a particular original BIN remain unqualified. |
| Section 4 | All embedded byte arrays and their provenance comments; copying, high-speed patches, erase/write bank patch offsets and framing use. | The HC11 machine instructions were not independently reconstructed or hardware-executed. Kernel origin is explicitly described in source as OSE V1.5.1 decompilation; this review does not establish third-party redistribution rights. |
| Section 5 | Complete `ALDLProtocol`: frame builders, length/checksum calculations, seed/key calculation and Mode 1 decoding control flow. | Malformed input and response correlation findings were sent to the integration owner. Existing synthetic tests cover selected builders; they do not establish the physical protocol or authenticate an ECU. |
| Section 6 | Complete `BaseTransport`, PySerial and D2XX wrappers, and complete `LoopbackTransport`, including load/export, simulated commands and address remapping. | No COM/USB device was opened. D2XX driver behavior, serial partial I/O and electrical bus behavior remain untested. The loopback emits synthetic acknowledgements and does not execute uploaded HC11 code, validate a real checksum command, enforce all security states or prove hardware equivalence. |
| Section 7 | Settings/recovery serialization and complete `ECUComm` control flow: callbacks, cancel state, locks, TX/RX, retries, echo/heartbeat, silence, seed/key, programming/kernel, chip ID, erase/write, verification/reset and read APIs. | Findings include false reset-success, response-shape/correlation gaps and unsafe saved configuration values. Integration fixes/tests are separately recorded. Physical state transitions, programming commands, checksum kernels and recovery remain on hold. Recovery-state JSON is metadata, not a verified recovery image. |
| Section 8 | Complete `BinFile` load/save/CAL export, checksum, sector diff and table APIs. | Checksum arithmetic and table offsets are not independently validated against physical ECU firmware. CAL containers/padding are transformations, not evidence of reading missing bytes. Table APIs remain low-level: arbitrary caller-supplied metadata/value shapes are not comprehensively qualified. |
| Section 9 | Complete `FlashOp` reconciliation and safety edits in this lane: exact bounded reads, cancellation, cleanup, sparse backup and original-input preservation. | Targeted retained/new safety suite plus synthetic vECU checks passed before subsequent integration edits: 113 tests and 11 subtests. This is not a hardware or durable-recovery qualification. Captures are diagnostic evidence; incomplete reads are not complete BINs. |
| Section 10 | Complete `DataLogger` lifecycle, CSV creation, polling, buffering and callbacks. | Output collision/thread-failure findings were sent to the integration owner. Polling scheduling and shutdown under a real slow/unresponsive adapter remain untested. |
| Section 11 | Complete `LiveTuner` shadow loading, cell indexing, delta checks, batching, transmission, sensor guards and revert behavior. | Physical live tuning is held. Missing/nonfinite sensors must not establish safety. Byte-indexed table editing and the assumed shadow-address protocol are prototypes, not a validated control system. |
| Section 12 | Complete `FlashWorker` setup/run/chaos paths; `MainWindow._start_flash_thread`, `_start_flash_op`, `_on_read_data` and `_on_flash_finished` connections relevant to read admission and cancellation. | The rest of the approximately 3,000-line GUI section was not individually inspected in this lane. Separate existing GUI tests exercise widgets/actions; their existence does not imply every user interaction or hardware action has been qualified. |
| Sections 0, 13, 14 | Outside this core lane except imports/configuration necessary to run synthetic tests; portability/CLI owner reviewed these paths. | Refer to `PORTABILITY_AND_PUBLIC_AUDIT_20261020.md` and `SCRIPT_REVIEW_20261020.csv`; do not infer this lane independently reviewed every CLI branch. |
| `virtual_128kb_eeprom.py` | Complete executable code, logging/file I/O, state machine, programming/erase helpers, polling and bank mapping inspected by the delegated decoder/simulator review. | Functional simulation only. No cycle timing, voltage, actual Am29F010 die behavior, sector protection hardware or command compatibility validation. |
| `tools/hc11_disassembler.py` | Complete decoder, prefix control flow, operand formatting, annotations, CLI/self-test and opcode-table structure inspected by the delegated decoder/simulator review. | Individual opcode truth/cycles and VY annotations were not exhaustively checked against an external authoritative manual or real hardware. Synthetic tests establish only the cases actually exercised. |

Material findings from this review were sent directly to the integration owner.
The final source, test evidence and release notes determine which findings were
fixed and which remain explicit holds; this inspection ledger is not a blanket
statement that every script, GUI path or hardware behavior is correct.
